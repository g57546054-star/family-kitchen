本文件是供项目拥有者后续手动操作的说明；PR、npm 安装、CI、本地测试均不会执行这些操作。开发期间没有连接腾讯云、创建集合、部署函数、购买套餐或调用云资源。正式微信官方编译与真实多人联机验收尚未完成。

## 1. 先确认体验环境与权限

1. 使用有该小程序开发权限的微信账号登录稳定版开发者工具，从仓库**根目录**导入项目，确认 AppID 与 `miniprogramRoot`。本地执行 `npm ci`、`npm ci --prefix miniprogram`，工具里点击“构建 npm”。
2. 由项目拥有者在开发者工具的**云开发**面板选择上述已存在环境，核对它关联到正式 AppID，且数据库类型为文档型。若工具要求重新创建环境、开通付费、购买套餐或切换关系型数据库，应停止并核对已有环境，不照此提示创建新资源。
3. 右键 `cloudfunctions/` 选择该环境（菜单名称可能为“当前环境/切换环境”），确保后续所有手动操作都选中同一个环境。客户端环境在 `services/cloud-config.js`；函数使用 `cloud.DYNAMIC_CURRENT_ENV`，避免硬编码访问另一个环境。
4. 查看实际剩余免费额度、环境到期日及资源计费规则。下面的部署/联机测试会消耗云函数调用、计算、数据库操作等额度，只应在用户决定进行手动验收后执行。代码中没有自动续费或购买逻辑。

## 2. 手动创建集合并立即关闭客户端读写

在该环境的“数据库”面板，逐个新建下表9个集合，不需要预填任何用户数据。集合名大小写必须一致。**每个集合的安全规则均设置为自定义规则 `{"read":false,"write":false}` 并保存**，或选择等效“仅管理端可读写”，切勿选择所有用户可读写/仅创建者读写。

模板为 `cloudfunctions/database.rules.json`，集合清单为 `cloudfunctions/collections.json`。此文件只是说明，不会自动执行配置。普通小程序 SDK 不能直接查询或写任何集合；受信任云函数 SDK 的服务端管理权限绕过客户端规则，所以函数内仍必须执行成员校验。函数本身要允许**该小程序已登录用户**调用以支持创建/加入；不要开放外部匿名 HTTP 访问或配置通用超级管理员入口。

| 集合 | 文档 `_id` 与主要字段 | 用途与限制 |
| --- | --- | --- |
| households | `hh_<随机24位hex>`；name、memberIds、inviteIds、version、dataVersion、menuVersion、createdAt/By、updatedAt/By | 事务协调文档，最多20人、10个有效邀请 |
| users | SHA256(可信OPENID)前32位；householdId、version、updatedAt/By | 一人一个家庭的事务约束，不包含明文OPENID |
| members | `<householdId>_<uid>`；householdId、uid、name、role、active、joinedAt、version、updatedAt/By | 管理员/成员角色；移除保留停用审计记录 |
| invites | SHA256(随机12位HEX邀请码)；householdId、createdBy/At、expiresAt、maxUses=1、usedCount、usedBy/At、revokedAt/By | 30分钟有效，事务内核验签发管理员仍有效；不在邀请查询文档保存明文码 |
| recipes | `_id=householdId`；items数组、householdId、version、updatedAt/By | 家庭聚合文档，复用原生菜谱结构和单位校验 |
| plans | `_id=householdId`；entries对象、householdId、version、updatedAt/By | 聚合菜单，字段键为 `日期:餐次`；人数1—100，每餐最多30道 |
| shopping_checks | `_id=householdId`；keys数组、versions数组、householdId、version、updatedAt/By | 勾选与单项版本；用数组避免食材名成为非法数据库字段路径 |
| operations | SHA256(uid+请求编号)；uid、householdId、action、digest、result、createdAt | 持久幂等/审计记录；仅存简短结果，不存全量菜谱快照；邀请创建的重试结果含明文码，客户端规则必须关闭 |
| rate_limits | `_id=uid`；tick、calls、joins、expiresAt | 每分钟最多60次调用，其中加入尝试最多5次；失败猜码同样计数 |

模型选择按**小家庭规模的聚合文档**存储 recipes/plans/checks，不使用每道菜一个文档的无界查询。单份状态最多650KB，单项勾选版本记录最多128KB；版本记录在菜单变化时压缩清空。服务端校验成员、身份、所有入参和容量边界，UI 上的禁用按钮不是权限依据。

## 3. 索引配置

运行路径仅使用 SDK 文档事务里的 `collection(name).doc(id).get()` 和 `.set({data})`，不执行 `where`、排序、跨集合 SQL 或事务内查询。每个集合默认的唯一 `_id` 索引足够，**无须添加复合索引**。请在索引面板确认 `_id` 唯一索引已存在，不要重复创建。不要为 recipes.items/menus 大对象建立全字段索引。

可选：只有今后人工维护过期邀请/限流记录时，才分别给 `invites.expiresAt`、`rate_limits.expiresAt` 建升序普通索引以辅助后台清理。本版本不依赖 TTL 索引或后台触发器，不能假设体验环境支持 TTL。过期校验使用服务端时间，不能靠清理任务保障安全。

**不要删除 `operations` 幂等记录或对其配置 TTL**，否则旧客户端的同编号请求可能再次执行。它们也是审计记录；需要清理时，应先设计永久请求墓碑/世代机制并迁移版本，当前版本未提供。长期写入会增长数据库存储，请留意免费配额。

## 4. 手动部署唯一云函数

1. 本地在根目录执行 `npm ci --prefix cloudfunctions/family --ignore-scripts`，依赖锁定 `wx-server-sdk@4.0.2`。这只安装公开 npm 包，不会连接云环境。SDK 源码文档适配层已核对其事务 `runTransaction`、`get()` 的事务对象返回及 `set({data})` 形状；不存在的文档通过 `database({throwOnNotFound:false})` 返回 null，而不是吞掉所有数据库异常。
2. 确认 `cloudfunctions/family/shared/utils/core.js`、`shared/data/recipes.js` 已随函数目录存在。它们从原生逻辑直接复制；若更改过源逻辑，先运行 `node miniprogram/scripts/sync-cloud-domain.cjs` 并执行全部测试。不能只上传 index.js，也不能让函数依赖小程序目录之外的文件。
3. 开发者工具中右键 **`cloudfunctions/family`** → **上传并部署：云端安装依赖**，目标只能是上述现有体验环境。若需在面板手动新建函数，应使用同名 `family`、相同目录源码，**无触发器**。此步骤由用户后续手动执行，不在 PR/CI 自动运行。
4. 在函数配置中选择平台当前支持、满足 Node.js ≥18 的运行时，优先支持的 Node.js 20/22；内存先256MB、超时建议60秒，并根据实际体验环境可用选项调整。长事务与网络时延需真环境测量；不能以本地测试时长推算云端耗时。不要选择自动升级付费套餐的选项。
5. 不填写 AppSecret、API Key 或任何凭据。`config.json` 没有额外 OpenAPI 权限，微信服务端 SDK 使用平台运行身份。函数不能配置匿名 HTTP 路由。若函数 SDK/基础库兼容性报错，记录真实错误并修复，再验收，不放宽数据库安全规则。
6. 本地重新“构建 npm”并编译。点击“我的家庭 → 微信身份登录”，只有这时才发起实际云调用。`UNAUTHENTICATED` 通常表示游客号、AppID不符或不受信任调用环境；不要改成从 `event` 获取 OPENID 来绕过。

## 5. 初次迁移与真实双用户验收

先看 [README 的迁移步骤](../README.md#迁移到家庭)：导出本地文件 → 创建家庭 → 预览并备份切换 → 管理员向未编辑且只有自己的家庭一次性导入 → 最后邀请家人。加入现有家庭只切换视图，不上传个人数据。新家庭默认12道参考配方，导入时会明确确认替换该初始快照；其余情况服务端拒绝整份覆盖。大数据不要通过分批改写集合绕过限制。

至少用两个不同微信账号（开发/体验成员）完成以下人工验收，再决定是否对家人开放：

1. A创建家庭、导入带“个/毫升”的备份；B用邀请码加入，核对菜单、原单位、待核对标记与采购勾选。
2. B尝试管理员功能应拒绝；C非成员、另一个家庭成员不能读写A家庭。小程序客户端直接数据库 SDK 读取任意集合应被规则拒绝；测试完删除调试代码。
3. A/B同时点同道菜、同时加减人数，最终累加一致；同餐人数仍在1—100。编辑冲突保留表单；移除菜品冲突要求刷新，不能覆盖另一人操作。
4. A/B同时勾选不同食材，两项均保留；同时改同一食材产生冲突提示；改菜单后旧采购操作被拒绝且该周勾选按原规则失效。核对其他周。
5. 同一邀请码并发加入只成功一次；过期、已使用、已撤销码均拒绝。移除B后B再次拉取清空家庭内存视图，并拒绝写入；无法抹除对方已看过/手工备份的数据。
6. 模拟断网/响应丢失，应用重启后重新登录、重试待确认请求，人数不重复增加。未确认请求没有“直接丢弃再提交”按钮，避免结果未知时重复写入。
7. iOS/Android小屏与放大字体测试五个Tab、TDesign弹层、家庭昵称长文本、错误、邀请码复制和备份文件发送。

## 并发与同步约束

服务端所有数据写入均在文档事务内重新查 users/members/households，再执行领域命令。家庭协调文档参与写入，数据库冲突由 SDK 最多重试5次；并发人数采用服务端当前值的增量，绝不发送整份旧菜单。编辑/删除、点菜移除、清勾选等使用家庭 version 作为保守乐观锁，其他无关更新也可能导致重试提示。

recipes/plans/shopping_checks 的 version 与 household.dataVersion 在同一事务更新，pull 在事务中读取一致快照。shopping.set 检查 menuVersion 与单项勾选版本；同项冲突拒绝，不同项合并；菜单/菜谱用量变化会使旧勾选请求失效。邀请码事务同时消费次数、写成员与用户锚点，阻止并发重复加入/跨家庭占用。operations 与修改同事务提交，重复请求只返回原结果；重复请求编号用于不同入参会拒绝。

前台20秒拉取、页面重新显示/写成功后刷新及家庭页手动刷新，无实时监听。家庭页离开、Tab隐藏时停计时，编辑表单不做自动输入替换。每次拉取也验证成员，不以客户端缓存角色作为凭据。界面恢复本地模式不会自动向云端写回数据。

## 防滥用与成本

服务端每分钟限流文档的事务独立提交，失败邀请码猜测也消耗额度；单次请求<720KB，家庭状态≤650KB。12位随机HEX邀请码使用服务端密码学随机数（48位），30分钟一次性，最多10个有效码，仍应仅向可信家人转发。鉴权错误不返回数据库路径、原始OPENID、堆栈或请求内容；函数未把请求载荷写入日志。限流约束不能替代平台配额/防刷控制：大量不同微信身份仍可能消耗调用费，若开放到公众须另行增加平台限流/监控。

**免费体验不代表永久免费或无限资源。** 用户提供的是免费体验环境，按创建日起约6个月的体验周期规划，实际到期日、是否有月度刷新、可用资源和超额处理均以该环境控制台与当前合同为准，本 PR 未登录核验。须分别查看：云函数调用次数、GB·秒计算资源、函数并发、数据库读/写次数、存储容量、出网流量及备份保留；本地测试通过不消耗这些配额，但手动部署/联机验证可能消耗。

仅前台单设备20秒轮询约180次pull/小时；每次还有独立限流事务和成员查询，**一次pull不等于一次数据库读取**。小家庭聚合设计减少分页读和实时监听，但不是零成本。请在控制台查看调用与读写监控，关闭无需使用的前台页面；本版本不自动购买、续费或切套餐。

到期或额度耗尽可能导致服务暂停；数据保留/回收规则不能假定不变。请在到期前提前一月提醒家庭管理员，定期在备份页导出家庭JSON到设备外，演练切回本地恢复。若将来更换环境，须先导出、重新按本文安全规则配置，并明确迁移确认；仅改环境ID不会搬运数据。本地模式不依赖该体验环境，仍可使用原有菜谱与菜单。
