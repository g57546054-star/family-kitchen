# 网页数据备份与迁移

## 原则

旧网页代码、`localStorage` 键及数据没有被重写。小程序不能直接读取手机浏览器或电脑浏览器的 `localStorage`。迁移通过用户主动导出的 JSON 文件进行，没有自动上传。

网页数据版本为 `version: 1`；原生小程序活动状态为 `version: 2`。两套应用相互独立，迁移后网页仍可继续使用；后续编辑不会自动同步到另一端。

## 网页 → 小程序

1. 在**原先添加过菜谱的浏览器、原先的网站地址**打开网页。手机/电脑/其他浏览器的记录各不相同。
2. 网页左侧侧栏点击“导出备份”。手机版可先展开菜单。保存 `.json` 原文件，在确认迁移成功前保留该文件，不要清理网页网站数据。
3. 将文件发到微信文件传输助手，在小程序“备份迁移”中选择聊天里的 JSON；或复制文件内容到 JSON 文本框。
4. 点击“预览备份”，查看菜谱数量、点菜记录数和待核对食材数。这一步只读取和验证，不写本地存储。
5. 确认导入后按顺序执行：
   - 将用户提交的原 JSON **逐字符原样**写入独立备份键；保留原有空白、单位、收藏、菜单和旧勾选。
   - 自动保存导入前的小程序 v2 完整状态快照。
   - 验证合并结果，在单个活动键 `family-kitchen:mini:v2` 写入新状态。
6. 查看迁入菜谱、收藏与点菜记录，在采购页重新核对勾选。“自动保留的原始备份”可单独导出或复制原文件。

原网页菜谱 ID 被映射为 `web:<旧ID>`，与 `native:` 示例和 `private:` 新菜谱隔离；每周菜单引用同步映射。网页旧示例也会作为导入的私人菜谱保留，不用新示例覆盖它们。重复导入同一文件或已有同标识网页菜谱时拒绝导入，不猜测哪份较新、不覆盖本地修改。

迁移会取消新清单的采购勾选，因为本地菜单合并后用量可能改变。**旧勾选没有丢弃**：完整保留在网页原始备份中，不被误认为新清单已采购。

## 旧单位

示例：旧网页 `番茄 2 个 / 鸡蛋 3 个 / 油 15 毫升 / 盐 2 克` 迁入后仍是 `2 个 / 3 个 / 15 毫升 / 2 克`。前三项为 `needsReview: true`，第四项本身是质量单位。没有把鸡蛋默认按50克、番茄默认按150克或油按水密度来换算。

新原生示例的参考克重独立编写，不覆盖这份旧记录。它们也不证明旧配方已经称重。修改迁入菜谱时可继续保留原单位；如改成克重，需要重新填写实际称得重量并显式勾选已核对，`sourceMeasure` 留存原数量/单位。

采购清单仅统一克/千克；未核对的计数/体积单独列出，方便按原单位采购。

## 小程序备份与恢复

- “导出 JSON 文件”导出 `format: "family-kitchen-native-backup"` 的 v2 封套，包含当前菜谱、收藏、菜单、采购勾选及迁移记录。
- 微信文件发送需 `wx.shareFileMessage` 支持；开发者工具/游客模式可能不支持。可用“复制备份JSON”备用。取消发送不等于已经把文件保存在聊天中。
- **原网页文件和导入前快照不嵌入当前状态导出中**，需要在“自动保留的原始备份”逐个单独导出。请同时保存网页原文件与最新 v2 文件。
- v2 备份可在另一设备恢复活动数据；迁移记录中的备份键是来源设备的历史引用，不能证明新设备也有原文件。列表只显示当前设备真实存在的原始备份。
- 恢复 v2 是完整替换：预览后需再次确认；替换前先保存当前活动键的原始内容，即使它已损坏。它不会尝试覆盖并合并另一份未知版本的私人菜谱。
- “导出原始数据”用于抢救当前活动键；损坏内容仍原样导出，不保证可直接恢复。恢复入口接受标准 v2 封套，不把未知内容当成空菜谱。

## 失败与容量

- 语法无效、未知版本、无效日期/人数/单位、重复 ID、缺失菜谱引用、超过 1MB 的文件会在写入前拒绝。
- 原始备份或导入前快照任一写入失败，**不写活动键**。活动键写入失败时旧状态仍保留；可能留下已经成功保存的备份，它们仍可导出。
- 单个状态写入采用 `wx.setStorageSync`；代码只有在写入成功后才更新页面/提示成功。存储读失败或损坏时显示恢复入口，不自动显示可保存的空白状态，也不自动覆盖示例数据。
- 小程序本地存储有总容量限制，原始备份会占空间。本版不自动删除历史备份；请定期导出保存。出现空间不足时，可先通过开发者工具检查存储；清理前确认已保留所需文件。
- 原生状态与备份文件为 JSON。迁移标识采用稳定的非加密指纹，只用于避免重复导入，不是安全签名或防篡改证明。
